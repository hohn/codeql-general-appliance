#+TITLE: CGA Bench Internals

* Starting the UI

The normal command that serves the CGA Bench UI at
http://127.0.0.1:8610/ is:

#+BEGIN_SRC sh
cga -C cgabench/my-bench bench serve
#+END_SRC

The current live instance was started without automatic service management:

#+BEGIN_SRC sh
cga -C cgabench/my-bench bench serve --no-services
#+END_SRC

The command definitions are spread across several files.  The complete
=cga bench= command vocabulary is registered in one dispatcher line at
=cga/cga:47= and parsed in =cga/cgabench/cgabench/cli.py=.

* Commands invoked underneath

Some =cga bench= commands orchestrate other CGA components.

** Infrastructure

#+BEGIN_SRC sh
cga local-mrva preflight
cga local-mrva reset
cga local-mrva build
cga local-mrva start
cga local-mrva check
cga local-mrva stop
cga local-mrva cleanup
#+END_SRC

** Database preparation

#+BEGIN_SRC sh
cga db-lib getmeta PATH
cga db-lib download --force [--output-dir DIR]
#+END_SRC

** Query preparation

#+BEGIN_SRC sh
cga query-lib index DIRECTORY
cga query-lib pack
#+END_SRC

** Analysis lifecycle

#+BEGIN_SRC sh
cga mrva-request submit --name NAME --user USER
cga mrva-request status --name NAME
cga mrva-request download --name NAME
cga mrva-request verify NAME
cga sarif-ingest ingest --name NAME
#+END_SRC

=cga bench advance= selects the necessary lifecycle commands according to the
current D/Q/J/R state.  It does not run the entire sequence unconditionally.

* Operations that are not CGA commands

- Result filters and custom SQL use =/api/results= and =cgasi.store=.  DuckDB
  is invoked read-only.
- Catalogue discovery scans files directly.
- The system summary reads the sysview HTTP endpoint.
- D/R terminals manage PTYs directly.
- *Insert Copilot command* constructs =copilot --yolo ...=.  It does not invoke
  =cga=.
- Reloading, selecting cells, pagination, and terminal resizing are browser/API
  operations.
