\(t{=}40\) — \(J_{1.1}\) and \(J_{1.2}\) Complete; Scheduler Poll Cycle 4

This is the most complex event. Three things happen in rapid succession:

  • \(_1\): execute(\(\), \(R_1\)) completes → \(_{1.1}\)
  • \(_1 \): publish(\(_{1.1}\))
  • \(_2\): execute(\(\), \(R_2\)) completes → \(_{1.2}\)
  • \(_2 \): publish(\(_{1.2}\))

Step 2: Server Consumes Results from RabbitMQ

  • \( S\): consume(\(_{1.1}\))

  • \(S \): SetStatus(\(J_{1.1}\), \(_S\))
  • \(S _L\): TriggerScheduling()
  • \( S\): consume(\(_{1.2}\))
  • \(S \): SetResult(\(J_{1.2}\), \(_{1.2}\))
  • \(S \): SetStatus(\(J_{1.2}\), \(_S\))

Step 3: Scheduler Runs (triggered or on poll)

  • \(_L \): SELECT running → \(W_r{=}0\), \(W_a{=}2\) (both now \(_S\))

Fair Scheduling Decision — \(U_2\) prioritized:

\[(U_1) = (n_r,\; ,\; {-}n_p) = (0,\; 60,\; {-}1)\] \[(U_2) = (n_r,\; ,\; {-}n_p) = (0,\; 0,\; {-}3)\]

Priority comparison: first components tie (both 0); second component \(_{U_2}{=}0 < _{U_1}{=}60\), so \(U_2\) wins.

Priority order: \([U_2, U_1]\). \(W_a{=}2\).

Round-robin allocation: - Pass 1: \(U_2\) gets 1 slot → \(a_{U_2}{=}1\); \(U_1\) gets 1 slot → \(a_{U_1}{=}1\); remaining = 0

Result: \(J_{2.1} _1\), \(J_{1.3} _2\)

Note on fairness: \(U_2\) is prioritized because \(U_1\) has already consumed 60 s of compute time (\(60\)) while \(U_2\) has consumed 0 s. Even though both have \(n_r{=}0\), the second component of \(\) breaks the tie in \(U_2\)’s favor.
